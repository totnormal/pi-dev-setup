# Organize the Demo Around Differentiated Value

## R — Original Passage (Reading)

> A great product demo puts features in the context of the value they enable.
>
> — April Dunford, Step 5: Differentiated Value

---

## I — Methodology Skeleton (Interpretation)

A demo should not tour the product. It should prove the value themes that matter after the buyer has accepted the market frame. Features are shown only as evidence of value. Organize the demo by value themes, not navigation, modules, or every capability.

---

## A1 — Application in the Book (Past Application)

Funnel’s pitch does not show connectors as isolated features. It organizes the demo around bringing all marketing data together, giving marketing control over trusted data, preparing data automatically, and making it available anywhere.

## E — Execution Steps

1. **Step 1**
   - Select 1–3 differentiated value themes from positioning.
   - Completion standard: this step produces a concrete, inspectable note, list, decision, or revision.

2. **Step 2**
   - For each theme, choose only the features/screens/proofs that demonstrate that value.
   - Completion standard: this step produces a concrete, inspectable note, list, decision, or revision.

3. **Step 3**

## B — Boundary

### Do not use this skill when

- Do not use this to hide missing required features.
- Do not include every menu item.
- Do not call table-stakes capabilities differentiated value.

### Common failure modes from Dunford's books

- Treating positioning as copywriting rather than strategic context.
- Talking about features before clarifying alternatives and value.
- Using generic trends, generic problems, or generic proof.
- Letting the buyer infer the purchase criteria alone.
