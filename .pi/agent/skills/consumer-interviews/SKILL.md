# Synthetic Consumer Interviews

## What This Skill Is — And Is Not

### This skill CAN (real Pi functionality):
- Guide you through a structured research setup workflow, asking one question at a time
- Read documents you provide (PDFs, text, Markdown) and extract segment/product insights
- Generate synthetic consumer profiles, interview guides, and research outputs
- Write study state and reports to `./research/` as Markdown and JSON files
- Simulate interview dialogue with clearly labeled, formatted role-play turns
- Pause for your approval at every major decision point
- Save and resume studies between sessions

### This skill SIMULATES (prompt-based, single LLM context):
- Role-play between interviewer and respondent — **both are generated by the same LLM in the same context window, using different prompt instructions for each turn**
- Distinct personas — achieved through behavior and tone instructions, not separate models or API calls
- Interview dynamics — follow-ups, probing, natural flow are prompt-directed, not system-enforced
- There are **no separate LLM calls per role**. Each turn is a sequential output in one conversation.

### This skill CANNOT (would require a real app/backend):
- Make separate API calls for different agent roles
- Run interviews in parallel or asynchronously
- Interrupt generation mid-stream during autopilot mode
- Enforce turn limits programmatically (reliance on prompt instructions)
- Connect to external research platforms or databases
- Replace real consumer research — **all outputs are synthetic hypotheses**

---

## Activation

Use this skill when:
- You need to explore consumer attitudes, behaviors, or preferences qualitatively
- You want to test hypotheses about segments before committing to real research
- You need to prepare or test discussion guides for real interviews
- You want to explore "what if" scenarios with synthetic consumer profiles

## Architecture

```
consumer-interviews/
├── SKILL.md                 ← You are here (orchestrator)
├── agents/
│   ├── interviewer.md       ← Interviewer persona (loaded for interview turns)
│   ├── respondent.md        ← Synthetic respondent persona (loaded for respondent turns)
│   └── analyst.md           ← Analyst persona (loaded for analysis turns)
└── templates/
    ├── interview-guide.md   ← Default question dimensions reference
    ├── segment-profile.md   ← Segment profile schema reference
    └── study-state.md       ← Study state JSON schema
```

### Persona Loading

When generating output for a specific role, read the corresponding agent file and adopt that persona:
- Interviewer turns → read `agents/interviewer.md`
- Respondent turns → read `agents/respondent.md`
- Analysis outputs → read `agents/analyst.md`

These are all prompt-based behavior changes within the same LLM context.

### Output Labeling

Every interview turn uses these fixed prefixes:
```
🎙️ INTERVIEWER: [question or probe]
👤 [Name] ([Segment]): [answer]
📊 ANALYST: [analysis output]
```

## State Persistence

Study state is saved to `./research/study-state.json`.

**At startup:** Check if this file exists in the current working directory.
- If it exists: Offer to resume or start a new study.
- If not: Start a new study.

**Save points** (write to `./research/study-state.json` after each):
- After Phase 2: segments and product approved
- After Phase 3: respondents approved
- After Phase 4: interview guide approved
- After each interview: transcript and summary saved
- After Phase 6: final analysis saved

Additional files written to `./research/`:
- `transcript-[respondent-name].md` — Per-respondent interview transcripts
- `summary-[respondent-name].md` — Per-respondent summaries
- `synthesis.md` — Cross-respondent synthesis
- `full-report.md` — Complete research report

## Workflow

### Phase 1: Intake

ASK ONE QUESTION AT A TIME. Wait for the user's answer before asking the next.

**Step 1.1: Research documents**

Ask: "Do you have research documents you'd like me to analyze for this study?"

- If **YES**: Ask for file paths. Use the `read` tool to read each file. Analyze for consumer segments, product/service context, market context, consumer behaviors, and attitudes. Summarize what you found. Proceed to Step 1.3.
- If **NO**: Proceed to Step 1.2.

**Step 1.2: Manual segment and product input**

Ask about segments first, building one dimension at a time:
1. "What consumer segments are you interested in researching?"
2. For each segment mentioned, ask about dimensions one at a time: demographics, psychographics, needs, behaviors, pain points, purchase triggers, decision criteria
3. Then ask about the product/service/brand:
   - "What product, service, or brand are you researching?"
4. Ask about product dimensions one at a time: category, positioning, value proposition, competitors, pricing, research goals

**Step 1.3: Present findings for review**

Present:
- Identified consumer segments with descriptions
- Product/service/brand summary

Ask: "Here's what I've identified. Would you like to review and adjust before we proceed?"

---

### Phase 2: Segment & Product Approval

Present each segment as a formatted profile:

```
## Segment [N]: [Name]
**Description:** [1-2 sentence summary]
**Demographics:** [key characteristics]
**Psychographics:** [values, attitudes, lifestyle]
**Needs:** [primary needs]
**Motivations:** [what drives purchase behavior]
**Barriers:** [what prevents purchase]
**Purchase Triggers:** [what initiates consideration]
**Decision Criteria:** [how they evaluate options]
**Priority:** [High/Medium/Low]
```

Ask for review:
```
Review each segment. Available commands:
  approve        — Accept as-is
  edit [field]   — Modify a specific field
  merge [N] [M]  — Combine two segments
  split [N]      — Break into sub-segments
  remove [N]     — Drop this segment
  add            — Add a new segment
  reprioritize   — Change priority order
```

Wait for feedback on ALL segments. Iterate until approved.

Then present the product definition:

```
## Product: [Name]
**Category:** [...]
**Positioning:** [...]
**Value Proposition:** [...]
**Target Audience:** [...]
**Pricing:** [...]
**Competitors:** [...]
**Differentiation:** [...]
**Research Goals:** [...]
```

Ask for approval using the same commands. Iterate until approved.

**Save state.**

---

### Phase 3: Respondent Creation

For each approved segment, generate 2-3 synthetic consumers (the default; user can change).

Present each respondent profile:

```
## 👤 [Name] — [Segment]
**Label:** [Name], [age], [occupation], [location]
**Background:** [2-3 sentence life context]
**Lifestyle:** [daily routines, habits, context]
**Category Relationship:** [how they relate to the product category]
**Buying Behavior:** [frequency, triggers, process]
**Attitude Toward [Product]:** [current perception]
**Needs & Goals:** [what they're trying to achieve]
**Likely Objections:** [what would hold them back]
**Internal Tensions:** [contradictions in their thinking]
```

Ask for review:
```
Review each synthetic consumer. Available commands:
  approve                  — Accept this respondent
  edit [field]             — Modify specific fields
  regenerate               — Create a new profile for this slot
  regenerate [instruction] — Regenerate with specific guidance
  add                      — Add another respondent to this segment
  remove [name]            — Drop this respondent
```

Wait for approval of ALL respondents before proceeding.

**Save state.**

---

### Phase 4: Interview Guide Generation

Generate at least 20 interview questions. Read `templates/interview-guide.md` for the full list of required research dimensions. Each question must include:
- Main question text
- 2-3 follow-up probes
- Which research dimension it addresses
- Which segments it is most relevant for

Present the full guide as a numbered list with all metadata.

Ask for review:
```
Review the interview guide. Available commands:
  approve            — Accept the full guide
  edit [N]           — Modify question N
  remove [N]         — Delete question N
  add [text]         — Add a new question
  reorder [N] [M]    — Swap question positions
  regenerate         — Create a new guide from scratch
```

Wait for approval.

**Save state.**

---

### Phase 5: Interview Execution

For each respondent, in order:

#### 5.1 Pre-Interview

Show the respondent profile. Ask:
```
Ready to interview [Name] ([Segment]). Which mode?
  manual    — Approve each question and answer before proceeding
  autopilot — Generate full interview, review afterward
```

Default: **manual**.

#### 5.2 Manual Mode

Show the respondent profile as context. Then for each question in the guide:

**Step A — Interviewer question:**

Generate using the interviewer persona (`agents/interviewer.md`):

```
🎙️ INTERVIEWER: [question text]
```

Ask:
```
Approve this question?
  approve                    — Accept, proceed to answer
  edit [text]                — Modify question
  skip                       — Skip to next question
  follow-up [text]           — Add a follow-up question
  pause                      — Pause interview, save state
  end interview              — End early, proceed to summary
  moderator [instruction]    — Add guidance for next turns
```

**Step B — Respondent answer:**

Generate using the respondent persona (`agents/respondent.md`):

```
👤 [Name] ([Segment]): [answer]
```

Ask:
```
Accept this answer?
  approve                    — Accept, proceed to next question
  edit [text]                — Modify answer
  regenerate                 — Generate a new answer
  regenerate [instruction]   — Regenerate with specific guidance
  challenge [text]           — Challenge the respondent's answer
  skip                       — Skip, move to next question
  revise respondent          — Edit respondent profile mid-interview
  end interview              — End early, proceed to summary
  autopilot                  — Switch to autopilot for remaining questions
```

If `challenge` → generate respondent's response to the challenge, then continue.

If `revise respondent` → ask user for changes, update profile, continue with revised context.

If `autopilot` → switch to autopilot mode for the remaining questions.

Repeat Step A → Step B for each question or until the user ends the interview.

#### 5.3 Autopilot Mode

Show the respondent profile as context.

Generate the **complete** interview as a single transcript block. Use the interviewer persona for questions, the respondent persona for answers.

```
━━━ Interview: [Name] ([Segment]) — Autopilot ━━━

🎙️ Q1: [question]
👤 [Name]: [answer]

🎙️ Q2: [question]
👤 [Name]: [answer]

[... all remaining questions ...]

━━━ End of Interview ━━━
```

⚠️ **In autopilot mode, the user reviews the complete transcript AFTER it is fully generated. Mid-generation interruption is not possible in a Pi skill — the full block is generated before the user sees it.**

Present the complete transcript and ask:
```
Review this interview. Available commands:
  approve                  — Accept full transcript
  edit [turn N]            — Modify a specific turn
  regenerate [turn N]      — Redo a specific turn
  regenerate all           — Redo the entire interview
  challenge [turn N] [text]— Challenge a specific answer
  reject                   — Discard and start over
  manual                   — Redo this interview in manual mode
```

#### 5.4 After Each Interview

Switch to the analyst persona (`agents/analyst.md`). Generate:

```
## 📊 Respondent Summary: [Name] ([Segment])
⚠️ Synthetic respondent — these are hypotheses, not real consumer evidence.

### Key Insights
1. [insight] — Turn [N]
2. [insight] — Turn [N]

### Memorable Quotes
> "[exact quote]" — Turn [N]

### Motivations
- [...]

### Pain Points
- [...]

### Objections
- [...]

### Purchase Triggers
- [...]

### Competitor Mentions
- [...]

### Pricing Signals
- [...]

### Unresolved Questions
- [...]

### Stated vs. Revealed Preferences
- **Stated:** [what they said they value]
- **Revealed:** [what their emphasis/emotion revealed]
- **Contradictions:** [any gaps]
```

Ask for approval. Save transcript to `./research/transcript-[name].md` and summary to `./research/summary-[name].md`.

Proceed to next respondent.

#### 6.5 Limitations (MANDATORY — always include)

```
## ⚠️ Limitations of Synthetic Consumer Research

These findings are SYNTHETIC HYPOTHESES generated by AI, not evidence from real consumers.

- Synthetic consumers are simulations based on segment profiles and product definitions.
- They do not represent actual consumer opinions, behaviors, or attitudes.
- The interviewer and respondent are both generated by the same LLM — there is no true independent perspective.
- Findings should be validated through real consumer research before business decisions.
- Synthetic research is useful for: hypothesis generation, discussion guide preparation, and assumption exploration.
- It is NOT a substitute for real qualitative or quantitative consumer research.

**Recommended next step:** Conduct real interviews with consumers matching these segment profiles. Use this study's interview guide as a starting point.
```

Save to `./research/`:
- `synthesis.md` — Cross-respondent synthesis + segment comparison + opportunity map
- `full-report.md` — Complete research report including all sections above
- `study-state.json` — Updated study state with analysis results

Ask for approval of the final report.

## Mode Behavior

### Manual Mode (Default)
- Every interviewer question is shown for user approval before generating the answer.
- Every respondent answer is shown for user approval before the next question.
- User has full intervention capability at every turn.
- Mode can be changed to autopilot at any time by typing `autopilot`.

### Autopilot Mode
- The complete interview (all remaining questions) is generated as a single block.
- The user reviews the full transcript AFTER it is generated.
- Mid-generation interruption is NOT possible — this is a Pi skill limitation.
- After review, the user can: approve all, edit specific turns, regenerate turns, or reject and redo.
- The user can switch back to `manual` to redo the interview with turn-by-turn control.

### Mode Transitions
```
MANUAL ←→ AUTOPILOT
- "autopilot" at any point → remaining questions run in autopilot
- "manual" during autopilot review → redo interview in manual mode
- Mode is per-interview, not global
```

## Safeguards

1. **Label everything synthetic.** Every interview turn, summary, and finding includes a reminder that these are synthetic hypotheses.

2. **Never present as evidence.** Use language: "synthetic respondents suggested...", "the simulation indicated...", "hypothetically, consumers might..."

3. **Cite transcript turns.** Every claim in analysis must reference a specific respondent name and turn number. No unsupported assertions.

4. **Do not fabricate quotes.** All quotes must come directly from the generated transcript — verbatim, not paraphrased.

5. **Recommend real validation.** Final report must include the Limitations section and a recommendation for real consumer research.

6. **One question at a time.** During intake, never ask multiple questions in one turn.

7. **Pause for approval.** Always wait for explicit user approval at every major decision point: segments, product definition, respondents, interview guide, each interview turn (in manual mode), each summary, final report.

8. **No hidden assumptions.** If you need to make an assumption, state it explicitly and ask for confirmation.

9. **Context window management.** For interviews with many turns, periodically save the transcript to file. When context gets long, reference earlier turns by turn number rather than repeating full text.

## Resuming a Study

When `./research/study-state.json` exists:

1. Read the file.
2. Show the user: study name, current phase, interviews completed.
3. Ask: "Resume this study, or start a new one?"
4. If resume: Pick up at the last saved phase.
5. If new: Archive the old study (rename to `study-state-[date].json`) and start fresh.
